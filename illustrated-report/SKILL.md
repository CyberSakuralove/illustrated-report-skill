# 图文可读报告

让读者沿着证据和计算理解内容。图展示关系，公式精确表达变换，文字解释目的、理由与条件。简洁来自选择合适的表达和删除重复，不来自省略必要的中间步骤。

默认中文、简洁说明风格。语言、读者、范围和格式以用户要求为准；本技能不规定题材、页数、目录、图文比例、公式数量或必须举例。

## 动笔前建立阅读主线

- 从材料和已有对话确定读者已经知道什么、读后要理解或决定什么、需要覆盖哪些内容。能合理推断的直接推进；只为会改变范围或结论的缺口询问。
- 在工作笔记中理清主线：已有输入或证据 → 关键变换或判断 → 结果 → 用途。机制说明按依赖展开；决策报告按结论和证据组织，不强套相同模板。
- 先选一条配置或过程讲通，再安排阶段、分支与替代方案。复杂计算先拆回熟悉的局部操作，再合并总式；实现细节只有在帮助当前阅读任务时才展开。
- 未指定格式时默认 PDF，并保留可编辑正文和图表源文件。聊天内说明或用户指定的轻量格式不强制做成文件。

## 让证据支持叙述

先读给定材料与相关原始证据，重要结论保留可追溯出处。区分已验证事实、设计意图、解释、候选和待验证内容；不要把示意图、合成数据或局部测试当成真实运行结果。

数量写明单位、条件和分母；比较使用一致口径。材料不足时明确缺口，不补造结果、引文或因果关系。外部信息只补实际缺口，优先原始论文、官方资料或可核查实现；遵守用户限定的来源范围。

## 让概念和状态接得上

- **新概念从已知内容长出来。** 接住前文的对象、公式或操作，说明新术语是在给哪个结果命名、解决哪一步的问题，再继续展开。不要先插入孤立的词典式定义，让读者自己寻找关联。
- **关键中间步骤不能藏起来。** 说明模块的输入来自哪里、经过什么操作、输出代表什么、交给哪里。投影、编码、移位、筛选或汇合若改变了对象，就在图中或相邻公式中写出；只有形状相同不足以说明两个对象如何相连。
- **阶段与配置有边界。** 输入来源、可见信息或更新方式变化时先标明当前阶段。替代方案指出替换原过程的哪一步，再比较同一层级的输入和输出；局部子过程与完整过程不能不加区分地共用结果名称。
- **循环画清时间。** 分开本轮输出产生、下一轮消费、状态更新三个时点，交代何时计入历史、缓存、库存或累计值。根据问题选择时序图、状态表或分步式，不必逐轮重复全部计算。
- **每节接住上一节。** 前一结果应成为下一节可识别的起点；重要结果要有去向，或说明到此完成。标题和名词之间的顺序不能替代推理上的连接。

## 符号和公式有来处

以下规则用于确有符号、数量或公式的材料；纯叙事内容不必为满足格式另造符号。

- **来源、含义、用途就地说明。** 新变量、函数、上下标或维度首次出现时，紧贴公式或图用可读小字解释：它从哪个已有对象经何种操作得到、表示什么、接下来做什么。必要时补形状、单位、取值范围；不机械要求每个符号填满固定字段。
- **同一对象保持命名。** 索引、合并或变换确需新符号时交代对应关系；独立对象或独立计数才另起名字。区分位置、特征、样本等编号，不把不同维度在后文悄然设成相等。
- **第一次计数就讲清口径。** 先说数什么、怎样得到、包含和排除什么，再使用长度或总量。口径随阶段变化时明确变化，不能到损失、成本或结论处才补定义。
- **公式不只是给答案。** 关键式解释结果用途、运算先后和关键项为何存在。用括号或分步等式划清范围；缩放、归一化、阈值等项要说明其作用与适用条件。能由局部推导的先推导；设计选择与带假设的解释不要写成必然定理。
- **按读者已有知识取舍。** 熟悉的标准运算不必逐次解释，新参数和它在当前过程中的作用仍需交代。文末符号表只能作索引，不能替代首次说明；图和伪代码也遵守同一标准。

## 用图和公式减少阅读负担

先确定本单元最难用文字说清的关系，再选表达。不是先摆一串同形方框，再把正文塞进去。

| 要说明的关系 | 可优先采用 |
| --- | --- |
| 输入来源、变换、输出去向 | 数据流、局部展开图、相邻公式 |
| 先后、反馈、状态更新 | 时序图、状态表、步骤图 |
| 数量怎样得到、怎样增长 | 分步推导、矩阵或面积示意、真实数据图 |
| 方案在哪一步不同 | 对齐的结构对照、短表、同层级公式 |
| 真实运行或使用效果 | 保留必要上下文的实际截图 |

图或公式负责表达关系，正文补充动机、原因、条件和意义；图注帮助读图。删掉三者之间的重复，保留理解必需的解释。没有解释价值的图可以省略，不要求每页一图；算例与具体场景按读者需要使用，不强制手算或举例。

准确图表优先使用可编辑的代码或矢量表达。少量颜色保持语义稳定，连线标明传递什么或经过什么操作。不要为追求花样换图，也不要让所有不同关系都长成同一类框图。版式遇到问题时参考 [图文组织模式](references/layout-patterns.md)。

## 首稿交付前完成闭环

检查属于制作工作，先自行补足缺口，再交给用户评阅。依据篇幅、读者知识和材料复杂度选择检查深度，不把下列项目扩成机械打勾的附加报告。

1. **沿主线读。** 假定读者只掌握前文，走完关键输入到结论。遇到新对象，能否向前找到来源、向后找到用途？跨节、阶段和配置切换是否明确？
2. **核对符号与机制。** 检查命名、计数口径、单位和必要形状；检查公式括号、运算顺序、关键项的理由；检查图、正文和公式是否讲同一条计算或判断链。
3. **核对覆盖与证据。** 开头、中段、末段使用同一解释标准。修订任务逐页覆盖用户指定范围，检查关联引用；不要只改前文或规则，留下后半段旧问题。结论须落在材料实际支持的范围内。
4. **查看最终文件。** 使用实际渲染检查中文、字号、图中文字、公式、箭头、分页、截断与引用。导出成功不能代替看图；内容放不下时调整结构或拆分，不靠缩小字号掩盖问题。
5. **确认可用。** 核查交付版本、链接、可搜索文本、编辑资源和重建说明。只报告真实完成的检查；未验证的部分如实说明。

长报告、新领域或状态与公式交织的材料，可加一次独立读者审查：让审查者只依据正文追踪关键链条，指出无法从已有内容推到下一步的位置。其余适用的检查方法见 [解释与首稿检查](references/explanation-review.md)。这些方法减少可预防的反复，不承诺任意题材都能一次完美。

## 制作与交付

按 [制作与交付](references/output-workflows.md) 选择当前格式需要的工具；仅加载实际使用的文档或绘图技能，不把普通报告自动变成网站、幻灯片或额外实验。

正文保持连续可读。工作笔记、检查日志和制作经过留在交付说明或工作目录，只有属于读者任务时才放进报告。交付主文件、可编辑源与必要资源，简要说明内容范围、真实验证结果及使用所需的限制。
