# 图文组织模式

只在需要确定内容单元、版式或图文分工时读取。本文件给出可选组合，不是固定目录模板。

## 从读者的问题选择组合

| 阅读任务 | 一个单元如何展开 | 图最适合承担的任务 |
| --- | --- | --- |
| 理解技术或项目 | 一个具体场景 → 输入输出 → 关键判断 → 已知边界 | 跟踪信息经过哪些模块，在哪里分支或失败 |
| 判断研究候选 | 要解决的问题 → 机制 → 与已有方法的差别 → 验证与停止条件 | 显示真正改变的环节，保留相同部分作对照 |
| 看懂实验结果 | 结论 → 条件和对照 → 主要证据 → 解释与限制 | 展示比较、分布、误差或失败，不只显示最佳值 |
| 选择方案 | 决策标准 → 少量关键差异 → 证据 → 取舍 | 显示差异与代价；精确数值可以用短表 |

覆盖范围与篇幅分开处理。例如多个研究方向可以先用短总览定位，再详述仍有决策价值的方向，简述其余方向及淘汰理由。不要把“精简”理解为只留下最喜欢的两项。

## 让图和文字互补

下面是虚构例子，仅演示表达，不代表真实系统或评测：

**问题与边界**：用户询问旧版和新版接口是否兼容。系统需要分别找到两版的依据，不能仅凭新版描述推断旧版行为。

**图中应画**：同一个问题分流到旧版与新版证据检索，再汇聚到版本差异比较；任一版本证据不足时，分支走向“报告缺口”。箭头标注问题、证据或判断，不用相同连线混淆执行顺序与数据来源。

**图注**：两版分别取证，避免将一个版本的依据套用到另一个版本。

**正文解读**：这个流程说明系统预期如何保留版本边界。它本身不能证明系统已经实现，也不能证明比较结果正确；实现与正确性仍需代码和测试支持。

这组图文各有任务：段落交代问题，图呈现关系，图注给出读法，解读指出意义和证据边界。

## 可选页面布局

- **上下展开**：短结论 → 通栏图 → 解读。适合长机制图或需要按顺序阅读的说明，通常是中文报告的稳妥起点。
- **左右对照**：图与短解释并排。仅在两侧都可读时使用；不要把长段正文挤进窄栏。
- **总览加展开**：开头用一幅简图或短表建立全貌，再按问题展开。大图不应承担所有术语和细节。

短报告可以直接进入内容，不需要独立封面、摘要、目录各占一页。长报告按阅读需要加入导航与附录。

## 出现这些症状时优先改结构

| 症状 | 优先修正 |
| --- | --- |
| 图中文字接近整页正文长度 | 将解释移到正文；只保留图中必须看到的实体与关系 |
| 不放大就看不清图注或标签 | 拆图、减少分支或改为通栏；不要靠继续缩字适配 |
| 每段都被包进彩色卡片 | 恢复连续正文，只突出影响判断的结论或警示 |
| 图上箭头很多但不知道在传什么 | 标清关系类型；必要时将结构与执行顺序分开画 |
| 图和正文说了同一句话 | 图保留关系，正文解释条件、反例或意义 |
| 表格单元格塞进多行论述 | 留下可比较的字段，把论证移回正文 |
| 页面很漂亮但说不出结论依据 | 补回具体例子、原始证据和适用条件 |

## 最终尺寸下的可读性

A4 正文可从约 11–12 pt、图中文字约 9.5–10.5 pt 起步，按字体和图形复杂度调整。这只是排版起点，不是硬阈值，也不能替代实际查看。

使用少量语义稳定的颜色，颜色之外再用文字或线型区分状态。图表以真实比例和统一条件比较，柱图通常从零开始；确需截轴时明确标示。图片不得拉伸变形，真实截图应保留理解操作或结果所需的上下文。
