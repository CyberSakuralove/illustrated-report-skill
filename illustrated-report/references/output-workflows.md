# 制作与交付

只读当前交付格式所需的部分。用户指定的模板、工具、存放位置和格式优先；不要同时制作所有格式。

## 选择最少且足够的工具

本技能负责内容和阅读设计，格式工具负责生成与渲染。优先使用已有运行时和能力；不要为了普通报告新增外部账号、网站部署或一整套工具链。

- **PDF**：未指定格式时的文件交付默认项。公式、中文长文或机制图较多时，可选 LaTeX 与 TikZ；一般图文也可用稳定的 PDF 或 HTML 打印流程。读取当前环境适用的 PDF、LaTeX 技能，遵守其实际要求。
- **Word**：用户需要在 Word 内改文稿时使用 DOCX，读取 documents 技能；同时保留图的可编辑源文件。PDF 预览按需要提供。
- **本地 HTML**：用户明确需要屏幕阅读或交互时使用，也可以作为生成 PDF 的来源。默认本地交付，不把报告任务自动变成建站发布任务。
- **Markdown**：用户指定时交付，图片使用可携带的相对路径。若有 Mermaid，确认目标阅读器能渲染；不能确认时保留源码并提供可见的图像版本。

制作数量图表时使用真实数据。复杂统计图优先使用标准绘图库；简单且能核查比例的图可用程序化 SVG，不为小图新增不必要的依赖。机制图按需要使用 SVG、TikZ、draw.io 或 Excalidraw。只有实际选用工具时才加载相应技能。没有某个可选插件时，使用现有能力，不将其变成完成报告的硬依赖。

## 文件组织

使用用户指定位置，否则在工作区建立有意义的报告目录。以最少文件完成交付，例如：

```text
report-name/
  报告.pdf              # 最终阅读版，或用户指定的 docx/html/md
  source/               # 生成该版报告的可编辑源文件
  figures/              # 实际引用的图片与图表源文件
  _build/               # 编译日志与渲染预览，不混入最终文件
```

已有报告优先就地编辑其源文件，避免产生一串无法判断新旧的 final-v2-final 文件。若覆盖会丢失用户原稿，保留原稿或生成明确命名的修订版。外部图片记录出处；必须随源文件交付的资源不能留在临时目录。

## PDF 与 LaTeX

- 中文使用确实可用的中文字体和引擎，例如 XeLaTeX 配合 ctex；不把某台机器的字体路径或 TeX 可执行文件绝对路径写进可移植源码。
- 图表保留可编辑源文件；公式较多时避免把整页内容栅格化。
- 编译后检查缺字、溢出及未解析引用等相关日志；有交叉引用时编译到引用稳定。
- 将最终 PDF 的所有页面渲染为图片，查看中文、图中文字、分页、图注与引用。可用 `pdftoppm -png input.pdf preview/page`，也可用现有等价工具。
- 文本提取可辅助检查内容遗漏，不能证明页面没有重叠或截断。编译日志干净也不能替代看图。

## Word

- 使用标题样式、正常段落和可编辑表格；不要把全文截图贴进文档。
- 按所用文档技能渲染最终 DOCX，检查分页、表头、图片及图注的连接关系。
- 保留图片或图表源文件，确认交付给用户的文件本身能正常打开，不依赖作者机器上的临时链接。

## HTML

- 明确是本地阅读文档；除用户要求外，不新增登录、后台或部署。
- 设置合适的正文行长、行距和小屏布局；图像使用可缩放尺寸。需要 PDF 时加打印样式，检查分页后图文仍对应。
- 结构图优先内嵌 SVG 或随文件交付；不依赖未打包的本地绝对路径或不稳定 CDN 才能显示关键内容。
- 在实际浏览器中查看最终文件，检查屏幕尺寸及打印版中被截断的表格、图例、导航和图注。

## 交付前的最后一轮

以读者身份查看最终版：能否快速定位核心问题，图是否解释了正文难以直接表达的关系，正文是否补足了图无法表达的条件和含义。

只声明实际完成的检查。渲染失败时保留源文件、说明缺失能力，并明确该格式尚未完成视觉验收；不能把未检查的导出件称为可读性已验证。

提供主文件、编辑所需资源和最短重建命令或说明即可。需要独立复现时，将命令保存在交付目录的小文件中；普通报告无需额外生成详尽的 QA 账本。
