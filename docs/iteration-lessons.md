# 从初版到成品：怎样把阅读问题变成通用规则

Transformer demo 从初版到最终 19 页版本，主要问题并非缺少术语，而是读者需要自行补齐术语之间的联系。后续修改把这些联系放回正文、图和公式，读者最终认可了报告质量。

下面记录问题与规则，不把 demo 的页数、专用符号、结构或绘图工具变成下一份报告的模板。

| 初版或中间版本的问题 | 在 demo 中怎样暴露 | 提炼出的通用规则 | 首稿交付前怎样发现 |
| --- | --- | --- | --- |
| 图单调、文字多，重点不清 | 不同关系反复用同类框图，解释文字重复图意 | 先明确本节最难讲清的关系，再选择数据流、时序、公式或对照；正文解释理由与条件 | 图能否回答一个明确问题？删图是否损失理解？文字是否只在重复图？ |
| 符号只有名字或形状 | 隐藏向量、中间状态或查询向量出现时，没有生成过程 | 第一次使用新对象，说明从哪个已知结果经什么操作得到、代表什么、用于哪里 | 反向追溯每个关键对象，能否找到实际输入与变换？ |
| 命名和维度变化没有交代 | 同一结果在后文消失；一般维度被悄然当成相等 | 同一对象沿用名字；变换或独立对象需要新名称时明确对应关系，特定配置另行注明 | 核对名称、下标、单位和必要形状；重要输出是否有去向？ |
| 公式完整，机制仍然不清楚 | 缩放项只给符号，softmax 与后续乘法的范围不明确 | 公式同时解释用途、运算顺序和关键项为何存在；用括号或分步式消除歧义 | 能否说出先算哪一步、结果用来做什么、去掉关键项会怎样？ |
| 定义或计数说明太晚 | 长度、结束标记和填充的口径到后文才补 | 数量首次出现就说明数什么、怎样得到、包含与排除什么 | 第一次看到数量时，能否仅靠当地内容确定它的口径？ |
| 章节之间跳过了重要变换 | 目标表示怎样成为查询、源表示怎样成为键和值，被压成一句话 | 按输入 → 变换 → 中间状态 → 输出用途组织，关键操作不能藏在箭头里 | 连续读相邻两节，前一结果能否自然成为后一节起点？ |
| 新术语成为孤立定义 | logits 先被抽象解释，没有接住已有词表映射 | 从已建立的公式或操作引出术语，说明它给哪个已有结果命名 | 读者是否需要回头猜新名称究竟对应前文哪一步？ |
| 阶段与配置混用 | 训练、生成、缓存更新混在一起；不同归一化排列像在同时定义一个输出 | 先讲通主线，再标明阶段或替代配置；比较同一层级的输入和输出 | 图、公式和正文是否在使用同一阶段与同一配置？ |
| 输出与状态更新的时间混淆 | 刚选出的 token 被误当成已经进入缓存的 token | 循环中区分输出产生、下轮消费和状态更新；数量在对应时点变化 | 每个关键时点的输入、状态和输出分别是什么？ |
| 后半段突然变成实现或名词清单 | 读者还在理解二维计算，就跳到批量张量、总成本式和组件名称 | 保持与读者任务匹配的抽象层级；成本从已知操作推起；替换说明旧步骤、新步骤和接回位置 | 后半段是否仍像前半段一样解释来处、作用与去向？ |
| 修订只覆盖局部，导出通过代替全文验收 | 前面修好了，指定的后续页段仍保留旧问题 | 对整份报告执行同一标准，修订时逐页覆盖指定范围；语义与渲染分开检查 | 先追踪整条解释链，再实际查看最终页；核对修改范围和关联引用 |

## 这些规则怎样进入 skill

规则按工作中的判断归并到五个位置：阅读主线、概念与状态连续性、符号与公式、表达选择、首稿交付闭环。细节检查留在按需读取的 reference 中，避免主文件累积一串互相重复的禁令。

首稿闭环是：在作者工作中先建立关键依赖，成稿后以读者身份沿链阅读、反向追溯新对象、核对阶段和计数，再渲染最终文件并修复问题。长文或陌生领域可增加独立读者审查；短报告不必生成额外流程材料。

## 泛化的边界

- “符号”可以是公式变量，也可以是流程中的状态、指标、角色或新对象；只有需要时才使用数学记号。
- “输入输出链”适合机制说明；研究、实验和决策材料也可以采用证据 → 比较 → 判断的主线。
- 图和公式减少啰嗦文字，但不能删除动机、条件、反例或证据边界。
- 实例、手算、图表数量、版式和工具由当前读者与材料决定；demo 的做法不是统一要求。
- demo 经过多轮审读。skill 的目标是把可预防的问题提前发现，不把一份成品当作对所有后续报告的质量保证。
